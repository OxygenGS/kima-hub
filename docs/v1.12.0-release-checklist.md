## Human functionality checks before stable tagging

Use a test instance with a nonproduction copy of data, **never an existing production mount or credentials**.

1. **Artist:** cold and warm artist navigation; library artists with 1 and 100+ albums; Play All, Shuffle, album sorting, discography, discovery-only artists, missing covers and requesting permitted albums.
2. **Album:** full track list, different disc counts, missing-track previews, request permissions, album playback, and return navigation.
3. **Library:** artist/album/track tabs, Next/Previous, URL history/back-forward, filters, sort, page size and cache reuse; no stale list when changing filter.
4. **Devices:** narrow mobile and desktop layouts (EN and NL), keyboard-only activation and visible focus, reduced-motion mode, and long album/artist titles.
5. **Integrations:** existing Symfonium and Feishin compatibility, freshly issued native API key with Legacy Authentication disabled, Symfonium sync with Compatibility Mode disabled. This improves **upstream's existing client support**.
6. **Security:** ordinary listener cannot bypass album-request/track-download rights; API-key revocation remains effective.

For performance measurements record cold/warm navigation-to-content timings, album/artist API request count and visible layout shifts. **Do not publish unmeasured percentage claims.**

## Controlled publication

1. Review changes since [v1.11.10](https://github.com/OxygenGS/kima-hub/releases/tag/v1.11.10), especially the Python BullMQ 3.2.8 dependency jump and its queue-worker compatibility.
2. Obtain explicit stable-release approval; then create `v1.12.0` on the verified main commit using the guarded stable-tag process. **Creating a tag alone does not guarantee a Docker image exists.**
3. Confirm the stable Docker workflow finishes native AMD64/ARM64 builds and image scans, publishes `ghcr.io/oxygengs/kima-hub:v1.12.0`, and reports its immutable image digest.
4. Verify the GHCR manifest contains both architectures and the GitHub release references the exact source commit. Only then update README and `docs/install.md` from v1.11.10 to v1.12.0.
5. Keep `:latest` unchanged unless deliberately and separately approved.

## Upgrade, safety and rollback

Back up the full **pre-upgrade** `/data` volume cold and confirm an independent restore before changing any existing instance. A rolled-back older image **must not** be started on a volume migrated by a newer image. Preserve the music mount and Compose project identity.

Follow [safe AIO updates and rollback](safe-aio-updates.md). Public release publication is not a deployment or authorization to alter someone's Docker/Dockge/Proxmox installation.
